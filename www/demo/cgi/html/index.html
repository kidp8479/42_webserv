How CGI works

When the server receives a request targeting a CGI script, it does not serve a static file. Instead:

1. the server forks a child process and executes the script via execve()

2. the request data (method, query string, headers) is passed to the script as environment variables

3. the POST body (if any) is written to the script stdin

4. the script writes its HTTP response to stdout, the server reads it and forwards it to the client

5. if the script hangs, the server kills it after a timeout and returns 504

File upload via CGI (browser form)

Browser forms send files as multipart/form-data - a format with boundaries and per-field headers that the C++ server does not parse natively.

The Python upload script handles this using the cgi module (Python 3.11 stdlib, bundled here since it was removed in 3.13). The script parses the multipart body, extracts the file, and writes it to disk.

This is why browser upload lives here on port 8086 (CGI) and not on port 8084 (raw C++ upload handler, curl only).
